# Security Policy

## Supported Versions

Security updates are applied to the latest release and the current active development branch.

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1   | :x:                |

## Reporting a Vulnerability

The Chronos team takes the security of our project seriously, especially given Chronos's role as a code governance and multi-agent authorization gate.

If you believe you have discovered a security vulnerability in Chronos:

1. **Do NOT open a public GitHub issue.**
2. Send an email to the maintainers with:
   - A description of the vulnerability and affected component (e.g. MCP auth bypass, lock race condition, hash-chain tampering).
   - Step-by-step reproduction instructions or proof-of-concept code.
   - Any proposed remediation or patch.
3. We will acknowledge receipt of your vulnerability report within 48 hours and provide an estimated timeline for remediation.
4. Once the issue has been patched, we will publicly credit you in our release notes (unless you prefer anonymity).
